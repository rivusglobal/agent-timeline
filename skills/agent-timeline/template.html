    How these numbers are computed
    • Source. The agent's own session log. It stores timestamps but no tool durations, so every duration is a difference between two timestamps.
    • Model time (faded blocks): from the last prompt or tool result to the end of the assistant message that follows. Tool time: from the end of that message to the last tool result. Parallel tool calls share one wall interval, charged to the slowest call's phase.
    • Phase of a tool call comes from its name and, for shell commands, a pattern match (test and lint runners are local commands, sleep/watch loops are polling, git and gh are git/PR). Patterns can misclassify unusual commands.
    • Waiting after a reply with no tool call is human wait if your prompt came next, otherwise async wait (background jobs or subagents). Gaps over 30 minutes are idle, excluded from "active" and drawn compressed.
    • Context compaction is read from the log's compaction record, which carries its own duration and token counts. That time is carved out of the surrounding wait or model time, and the synthetic summary message is not counted as a prompt.
    • Limits. Labels are the tool call's description or first command line, redacted for obvious secrets and truncated. Block boundaries are only as precise as log timestamps.
